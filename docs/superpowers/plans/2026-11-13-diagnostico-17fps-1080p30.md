# Diagnóstico dos 17 fps (H.264 1080p30) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native implementation in this session).

**Goal:** Instrumentar o encoder de vídeo do host (`outbound-rtp` stats) e o decoder do viewer (`freezeCount`, `totalInterFrameDelay`) para descobrir se os 17 fps observados na Fire TV AFTCA002 são limitação de CPU/encoder no Windows ou limitação do decoder da Fire TV / rede.

**Architecture:** Três camadas de instrumentação: (1) `capture.ts` passa `degradationPreference: "maintain-resolution"` + `scaleResolutionDownBy: 1.0` no encoder (opção b: nunca reduzir resolução); (2) `mirror.ts` lê `RTCRtpSender.getStats()` (entry.type === 'outbound-rtp', kind === 'video') via setInterval em `start()` e limpa o timer em `stop()`; (3) `Watch.tsx` acrescenta `freezeCount` e `totalInterFrameDelay` ao `inbound-rtp` debug. O lado do host revela `qualityLimitationReason` (`"cpu"` = encoder travado; `"none"` = não limitado localmente); o lado do viewer revela se o decoder está congelando (`freezeCount`) ou se há jitter entre frames (`totalInterFrameDelay`).

**Tech Stack:** TypeScript, Node 24, `node:test` + `node:assert/strict`, Electron 44 (WebRTC), Vite + React.

**Spec:** `docs/superpowers/specs/2026-11-11-h264-1080p-bitrate-stabilization-design.md` (Abordagem A, bitrate fixo 5 Mbps, opção b — resolução 1080p mantida).

## Global Constraints

- `RTC_CONFIG.iceServers` vazio e congelado (sem STUN/TURN) — `check:gates` valida
- Viewer é receive-only: sem `getUserMedia`/`getDisplayMedia`/`navigator.mediaDevices` em `src/viewer` ou `dist/viewer`
- Resolução nunca reduzida como válvula de escape (opção b): `scaleResolutionDownBy: 1.0`, `degradationPreference: "maintain-resolution"`
- Bitrate fixo 5 Mbps para 1080p e 720p; `native` isento
- `npm run verify` verde: lint (0 warnings), test (57/57), coverage (>= 90%), build, check:gates
- `CONSTRAINTS.md`: floor bloqueante inclui `npm run verify` antes de cada commit
